# Local Thai speech recognition

## ประมวลผลบน Client ก่อน

Engi เริ่มถอดเสียงบนเบราว์เซอร์เมื่อโมเดล Typhoon พร้อม โดยใช้ Web Worker และ ONNX Runtime WASM บน CPU ของอุปกรณ์ ผู้ใช้ยังเปิดโหมดเรียกชื่อหรือกดพูดผ่านหน้าเดิมได้

- เบราว์เซอร์จัดช่วงเงียบสองแบบและถอดเสียงทั้งคู่ ต้องตรงกันทั้งชื่อและคำสั่งในรูปประโยคที่รองรับ จึงส่งเฉพาะข้อความไปตรวจคำสั่งที่เซิร์ฟเวอร์
- คำเรียกไทย เปิด–ปิดแอร์ อุณหภูมิ และคำถามข้อมูลห้องมีเส้นทาง Client ส่วนคำสั่งพัดลม โหมด ประโยครวม ภาษาอังกฤษที่โมเดลไทยอ่านไม่ชัด และประโยคยาวกว่า 5 วินาที ใช้ Whisper บนเซิร์ฟเวอร์
- เมื่อผลสองรอบไม่ตรงหรือไม่ผ่านรูปประโยค ระบบส่งเสียงต้นฉบับให้ Whisper ภายในเซิร์ฟเวอร์ ประมวลผลบน Client ที่เกิน 1.8 วินาทีจะถูกยกเลิก และใช้ Whisper จนกว่าจะเปิดโหมดเสียงใหม่
- ช่วงโหลดโมเดลยังรับเสียงผ่าน Whisper ได้ Logs แสดงเมื่อโมเดล Client พร้อม รวมถึงเวลาที่ใช้แต่ละฝั่ง สถานะขณะประมวลผลระบุว่าใช้อุปกรณ์หรือเซิร์ฟเวอร์
- Browser โหลดน้ำหนักประมาณ 163 MB จากเซิร์ฟเวอร์ของคุณและแคชไว้ในอุปกรณ์ ไม่มีการส่งเสียงไปยังผู้ให้บริการ AI ภายนอก การโหลดครั้งแรกขึ้นกับความเร็วเครือข่าย
- อุปกรณ์ที่รายงาน RAM ไม่เกิน 2 GB หรือเปิดประหยัดข้อมูล ใช้ Whisper โดยอัตโนมัติ การปิดแท็บหรือปิดโหมดเสียงจะยุติ Worker และคืนหน่วยความจำ

### ติดตั้งน้ำหนักบนเซิร์ฟเวอร์ Windows

หลังอัปเดตโค้ด หยุด Node ตัวเดิมแล้วรันจากโฟลเดอร์โปรเจกต์

```powershell
.\.venv-voice\Scripts\python.exe .\scripts\download-browser-asr.py
npm.cmd start
```

สคริปต์ดาวน์โหลดเฉพาะไฟล์ที่ยังขาดหรือ checksum ไม่ตรง และตรวจ SHA-256 จาก revision ที่กำหนดก่อนเปิดให้เบราว์เซอร์ใช้งาน น้ำหนักอยู่ใน `models/typhoon-q4-v1/` ซึ่งอยู่นอก Git สคริปต์ `scripts/setup-windows.ps1` ติดตั้งส่วนนี้ด้วย

ที่มาของน้ำหนักคือ [Typhoon ASR Real-time](https://huggingface.co/typhoon-ai/typhoon-asr-realtime) โดย SCB 10X และทีม Typhoon ใช้ชุด [ONNX INT4 ของ saksornr](https://huggingface.co/saksornr/typhoon-asr-realtime-webgpu-q4/tree/2c547288276638a4823d8a108c81df9771f89c2a) ภายใต้ [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) การแปลง PCM และเส้นทางยืนยันคำสั่งในโปรเจกต์นี้ปรับสำหรับ Engi

การทดสอบอัตโนมัติใช้เสียงสังเคราะห์และไมค์จำลอง ความแม่นยำจากเสียงคนจริงหลายคน รวมถึงประสิทธิภาพบนมือถือจริงยังต้องตรวจบนอุปกรณ์ที่ใช้งาน

เส้นทางสำรองใช้ **Thonburian Whisper small ภาษาไทย + faster-whisper บน CPU INT8** โมเดลสำเร็จรูปนี้ผ่านการปรับฝึกภาษาไทยจากผู้พัฒนาเดิมแล้ว Runtime โหลดจากไฟล์บนเซิร์ฟเวอร์

แหล่งน้ำหนัก: https://huggingface.co/Thaweewat/whisper-th-small-ct2 (แปลงจาก biodatlab/whisper-th-small-combined), tokenizer: Systran/faster-whisper-small ดาวน์โหลดครั้งเดียวตอนติดตั้ง Runtime โหลดจาก absolute path ในโปรเจกต์ด้วย `local_files_only=True`, `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1` และตรวจว่ามี tokenizer ในเครื่องก่อนเริ่ม ไม่มีการส่งเสียงออกไปถอดที่อื่น

## ติดตั้งบนเครื่องใหม่

ใช้ Python 3.12 และ Node.js:

```sh
python3.12 -m venv .venv-voice
.venv-voice/bin/python -m pip install -r offline-voice/requirements.txt
.venv-voice/bin/python scripts/download-local-asr.py
npm install
npm start
```

น้ำหนัก ASR ใช้พื้นที่ประมาณ 0.5 GB การติดตั้งและดาวน์โหลดโมเดลต้องใช้อินเทอร์เน็ต หลังติดตั้ง Engi ถอดเสียงบนเซิร์ฟเวอร์ด้วยโมเดลในเครื่อง ส่วน MQTT.js โหลดจากเซิร์ฟเวอร์เดียวกับหน้าเว็บ ฟอนต์และ Chart.js โหลดจากภายนอก และการควบคุมอุปกรณ์ใช้ MQTT Broker ตามที่ตั้งไว้

ไฟล์ `models/whisper-th-small/manifest.json` บันทึกแหล่งและ SHA-256 สำหรับตรวจการติดตั้ง ไฟล์น้ำหนักไม่รวม Git ให้ติดตั้งแยกด้วยสคริปต์ข้างต้น

### ติดตั้ง Engi บน Windows

บน Windows x64 เปิด PowerShell ในโฟลเดอร์โปรเจกต์ที่มี `package.json` แล้วรัน

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-windows.ps1
```

สคริปต์ตรวจและติดตั้ง Node.js, npm, Visual C++ Runtime, Python 3.12, ไลบรารีของเว็บและระบบเสียง แล้วดาวน์โหลดโมเดลเมื่อไฟล์ยังมาไม่ครบ ใช้ตัวติดตั้งจาก Node.js, Microsoft และ Python.org พร้อมตรวจ checksum หรือ digital signature ก่อนรัน Windows อาจขอสิทธิ์ผู้ดูแลเมื่อติดตั้ง Node.js หรือ Visual C++ Runtime

รายการที่พร้อมแล้วจะแสดง `[skip]` ถ้า `.venv-voice` เดิมใช้ Python คนละรุ่นหรือเปิดไม่ได้ สคริปต์จะย้ายไปเก็บใต้ `.venv-voice-backups/` แล้วสร้างใหม่ สคริปต์ทดสอบโหลด Whisper จริงก่อนเปิดเว็บ ถ้าบัญชี Login ยังไม่มี จะให้ตั้งชื่อผู้ใช้และรหัสผ่านใน PowerShell

รันคำสั่งเดิมซ้ำได้หลังแก้ข้อผิดพลาดหรือรีสตาร์ต Windows หากต้องการติดตั้งและตรวจความพร้อมอย่างเดียว ให้เติม `-SetupOnly` ท้ายคำสั่ง เมื่อเว็บพร้อม ให้ล็อกอินที่ `http://127.0.0.1:3000/` และอนุญาตไมโครโฟนในเบราว์เซอร์ การเปิดผ่าน Cloudflare ให้ใช้ค่าของ Tunnel ตาม [คู่มือ Login](../LOGIN.md)

#### ติดตั้งเองทีละขั้น

ติดตั้ง Node.js และ Python 3.12 แบบ x64 บนเครื่อง Windows แล้วเปิด PowerShell ที่โฟลเดอร์โปรเจกต์ Python 3.12 ติดตั้งคู่กับ Python 3.15 ได้ สำหรับ Engi ให้ใช้ 3.12 เพราะ `onnxruntime` ที่ `faster-whisper` ต้องใช้ยังไม่มี wheel สำหรับ CPython 3.15 บน Windows x64 [รายการไฟล์ ONNX Runtime](https://pypi.org/project/onnxruntime/#files)

ถ้าใช้ Python Install Manager ให้รัน `pymanager install 3.12` ถ้ายังไม่มี Install Manager ใช้ [ตัวติดตั้ง Python 3.12.10 สำหรับ Windows x64](https://www.python.org/downloads/release/python-31210/#files) และเลือกติดตั้ง Python Launcher จากนั้นเปิด PowerShell ใหม่และตรวจด้วย `py -3.12 --version` ถ้าเคยสร้าง `.venv-voice` ด้วย Python รุ่นอื่น ให้เปลี่ยนชื่อโฟลเดอร์เดิมก่อนสร้างใหม่ [คู่มือ Python บน Windows](https://docs.python.org/3.12/using/windows.html#the-python-launcher-for-windows)

```powershell
npm.cmd ci
py -3.12 -m venv .venv-voice
.\.venv-voice\Scripts\python.exe -m pip install faster-whisper==1.2.1
.\.venv-voice\Scripts\python.exe .\scripts\download-local-asr.py
npm.cmd start
```

ถ้ามีน้ำหนักอยู่แล้ว คัดลอกโฟลเดอร์ `models/whisper-th-small/` ทั้งโฟลเดอร์มาไว้ในตำแหน่งเดิมบน Windows แล้วข้ามคำสั่งดาวน์โหลด Node.js จะเปิด `.venv-voice\Scripts\python.exe` โดยอัตโนมัติ หากติดตั้ง Python สำหรับ Engi ไว้ที่อื่น ตั้ง `VOICE_PYTHON` เป็นพาธเต็มของ `python.exe` ในสภาพแวดล้อมที่รัน Node.js หากยังไม่ได้สร้างบัญชีบนเครื่องใหม่ ให้ทำตาม [คู่มือตั้งค่า Login](../LOGIN.md)

### ตรวจเมื่อสถานะสลับระหว่างกำลังเตรียมโมเดลกับการฟังขาดช่วง

1. หยุดเซิร์ฟเวอร์เดิม เปิด PowerShell ในโฟลเดอร์โปรเจกต์ ตั้ง `$env:VOICE_DEBUG = '1'` แล้วรัน `npm.cmd start` ในหน้าต่างเดียวกัน เมื่อเห็น `Local Whisper พร้อมรับคำสั่ง • ไม่ใช้ AI API ภายนอก` โมเดลโหลดเสร็จแล้ว ถ้าพบ `ENOENT`, `ModuleNotFoundError`, `Missing local ASR file` หรือ `DLL load failed` ให้ตรวจพาธ Python, การติดตั้ง `faster-whisper`, โฟลเดอร์โมเดล หรือ Visual C++ Runtime ตามข้อความที่เห็น [คู่มือติดตั้ง CTranslate2](https://opennmt.net/CTranslate2/installation)
2. เปิด `http://127.0.0.1:3000/` บน Windows ล็อกอิน แล้วกด `F12` → `Network` ก่อนเปิดโหมดเรียก Engi ดูคำขอ `POST /api/voice-session` ถ้าได้ `503` หรือ `504` ให้ดูข้อความตอบกลับและบันทึกใน PowerShell ถ้าได้ `401` ให้ล็อกอินใหม่ ถ้าได้ `200` พร้อม `sessionId` โมเดลสร้างเซสชันได้แล้ว หากไม่มีคำขอออกมา ให้ดู `Console` และตรวจสิทธิ์ไมโครโฟนของเบราว์เซอร์กับการโหลดไฟล์ตรวจจับเสียงใน `Network`
3. ถ้า localhost ใช้งานได้แล้ว ให้ลองเปิดโดเมน Cloudflare ผ่าน `https://` และอนุญาตไมโครโฟนสำหรับโดเมนนั้น สิทธิ์ไมโครโฟนของ localhost กับโดเมนมีการตั้งค่าแยกกัน

## การพูด

- กดไมค์แล้วรอเสียงติ๊งเพื่อพูดคำสั่งตรง หรือเปิด “โหมดเรียก Engi” เพื่อรอชื่อก่อนคำสั่ง
- โหมดเรียก: “เอ็นจี้” หรือ “สวัสดีเอ็นจี้” → รอ “ครับ พูดได้เลยครับ” → เริ่มพูดภายใน 9 วินาที เช่น “เปิดแอร์ให้ผมหน่อย” หรือ “ปิดแอร์” รับคำสั่งได้หนึ่งครั้งแล้วกลับไปรอชื่อใหม่ หมดเวลาจะรอให้เรียกชื่ออีกครั้ง
- “เอ็นจี้เปิดแอร์ให้ผมหน่อย” → ส่งคำสั่งโดยไม่ทักทายคั่น ไม่ต้องเว้นชื่อเป็นอีกประโยค
- “เอ็นจี้ปรับอุณหภูมิ” → ระบบถาม “ต้องการกี่องศาครับ” → พูด “ยี่สิบห้าองศา” โดยไม่ต้องเรียกซ้ำ
- “เอ็นจี้ปรับพัดลมกลาง”, “เอ็นจี้เพิ่มพัดลมหน่อย”, “เอ็นจี้ลดอุณหภูมิ”, “เอ็นจี้โหมดลดความชื้น”
- เมื่อรอชื่อ ประโยค “เปิดแอร์” ที่ไม่มีชื่อจะถูกละไว้โดยไม่สั่งแอร์และไม่ขานตอบ Server ตรวจเงื่อนไขนี้ด้วย และผูกสิทธิ์คำสั่งถัดไปกับเซสชัน/อุปกรณ์เดียว ใช้ซ้ำไม่ได้ ระยะ 9 วินาทีเริ่มหลังเสียงขานรับจบ ถ้าเริ่มพูดทันจะรอให้พูดและถอดเสียงจบตามขีดจำกัด
- พูดหนึ่งประโยคได้สูงสุด 12 วินาที ไม่ใช้ขีดจำกัดเดิม 2 วินาที ถอดเสียงแล้วตรวจ grammar/ค่าตัวเลขก่อนส่ง ไม่ใช้ LLM เดาประโยคอิสระ
- ตรวจ Engi จากผลถอดเสียงและคะแนนตัวเลือกของโมเดลในเครื่อง โดยไม่ใช้คำใบ้ชื่อในช่วงรอเรียก การเรียกชื่อยังมีเวลาถอดเสียง และฟังได้เมื่อหน้าเว็บทำงานอยู่
- โหมดต่อเนื่องเก็บเสียงถัดไปได้หนึ่งประโยคขณะถอดเสียง คำสั่งที่ยืนยันแล้วส่งได้ทันที ส่วนเสียงตอบรอให้ประโยคถัดไปจบ ระบบทิ้งเสียงที่เริ่มก่อนเสียงขานรับเมื่อเปิดช่วงรับคำสั่งหลังเรียกชื่อ
- หากโหลดเสียงขานรับหลังเรียกชื่อไม่ได้ Engi จะใช้เสียงติ๊งจากเบราว์เซอร์เพื่อแจ้งว่าพูดต่อได้ เมื่อเซสชันเสียงหมดอายุ ระบบจะเปิดเซสชันใหม่และกลับไปรอฟังชื่อ
- ระหว่างพูดตอบพักไมค์ ป้องกันเสียงตัวเอง และเว้นหางเสียง 140 ms ก่อนกลับมาฟัง ยังไม่รองรับพูดแทรกเสียงตอบ
- มีการเก็บเสียงข้างต้น/ท้ายราว 320/512 ms และต่อ worklet เข้าทางออกเงียบเพื่อให้ Chrome ประมวลผลกราฟเสียงจริง
- ถ้าสถานะอุปกรณ์เปลี่ยนด้วยคำสั่งอื่นหรือเสียงรอเกิน 20 วินาที จะทิ้งคำสั่งค้าง ไม่สั่งจากสถานะเก่า
- ขณะรอเรียก หากยังไม่ยืนยันชื่อจะเงียบ ไม่ตอบหรือส่งคำสั่ง เมื่ออนุญาตให้รับคำสั่งแล้วและถอดไม่ชัด จึงขอให้พูดใหม่

## อุปกรณ์และขอบเขต

MQTT เดิมยังเป็น JSON `{POWER,TEMP,MODE,FAN}` รองรับ 21–27°C, MODE COOL/DRY/FAN, FAN AUTO/LOW/MED/HIGH สวิง/โหมดนอนและอุณหภูมินอกช่วงจะบอกว่าไม่รองรับ ไม่มีการแอบแปลงเป็นโหมดอื่น

เพิ่ม/ลดอุณหภูมิครั้งละ 1°C ต้องมีสถานะอุปกรณ์ตั้งต้น การสั่งตัวเลขเปิดแอร์ด้วย เทอร์โบแมป COOL 21°C HIGH / Eco แมป COOL 25°C AUTO คงขอบเขต firmware เดิม

เสียงตอบทวนเฉพาะคำสั่งที่ส่ง ไม่อ้างว่า IR ไปถึงแอร์จริง คำปฏิเสธและคำสั่งขัดกันถูกปฏิเสธใน grammar แต่ ASR อาจถอดคำปฏิเสธผิดได้ จึงไม่รับรองว่าป้องกันคำสั่งผิดได้ทุกกรณี

## โมเดลผู้ใช้เดิม

`models/ac_voice_model_int8.tflite` และ metadata เดิมยังเก็บไว้ คู่กับ `offline-voice/worker.py` สำหรับตรวจเทียบและพัฒนาต่อ ไม่มีการใช้ CNN นั้นตัดสินคำสั่งหลักหรือ fallback แบบเงียบ ๆ การแมป metadata ยังใช้เป็น allowlist ของคำสั่งอุปกรณ์ การทดสอบ legacy TFLite/MFCC ต้องใช้ TensorFlow/Librosa ใน requirements ด้วย

## ตรวจสอบ

```sh
npm test
.venv-voice/bin/python offline-voice/test_asr.py
.venv-voice/bin/python offline-voice/test_features.py
```

`test_asr.py` ปิด socket networking ก่อนโหลดโมเดลและทดสอบประโยคผู้ใช้ด้วยไฟล์เสียง Kanya สังเคราะห์ รวมประโยคยาวกว่า 2 วินาที เป็น regression test ของซอฟต์แวร์ ไม่ใช่การประเมินสำเนียงผู้ใช้จริง

ตรวจ Chrome โดยส่งเสียงสังเคราะห์ผ่าน MediaStream 48 kHz → Silero → WAV → ตัวถอดเสียงในเครื่อง → grammar → คำสั่งจำลอง ไม่เรียก callback ข้ามขั้น และปิด MQTT เพื่อไม่สั่งแอร์จริง ส่วนไมค์มนุษย์จริง/เสียงสะท้อนในห้องจริง/ESP32 IR จริง ยังต้องทดสอบหน้างาน

เสียงผู้ใช้ไม่ถูกบันทึกอัตโนมัติหรือส่งไปฝึก หากต้องการ fine-tune สำเนียงผู้ใช้ ต้องเก็บไฟล์เสียงจริงพร้อมป้ายกำกับ และกันผู้พูด/รอบบันทึกไว้ทดสอบ ห้ามใช้คะแนนชุดฝึกอ้างเป็นความแม่นยำหน้างาน
