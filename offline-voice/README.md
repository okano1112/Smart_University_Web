# Local Thai speech recognition

ระบบหลักเปลี่ยนจาก CNN จำแนกเสียง 2 วินาที มาเป็น **Thonburian Whisper small ภาษาไทย + faster-whisper บน CPU INT8** ไม่มี inference API, ไม่ใช้ API key และไม่มี fallback ไป cloud โมเดลที่ใช้เป็นโมเดลสำเร็จรูปที่ผู้พัฒนาเดิมปรับฝึกภาษาไทยไว้แล้ว ไม่ได้อ้างว่าเรา fine-tune ด้วยเสียงผู้ใช้ในรอบนี้

แหล่งน้ำหนัก: https://huggingface.co/Thaweewat/whisper-th-small-ct2 (แปลงจาก biodatlab/whisper-th-small-combined), tokenizer: Systran/faster-whisper-small ดาวน์โหลดครั้งเดียวตอนติดตั้ง Runtime โหลดจาก absolute path ในโปรเจกต์ด้วย `local_files_only=True`, `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1` และตรวจว่ามี tokenizer ในเครื่องก่อนเริ่ม ไม่มีการส่งเสียงออกไปถอดที่อื่น

## ติดตั้งบนเครื่องใหม่

ใช้ Python 3.12 และ Node.js:

```sh
python3.12 -m venv .venv-voice
.venv-voice/bin/python -m pip install -r offline-voice/requirements.txt
.venv-voice/bin/python scripts/download-local-asr.py
npm install
npm start
```

Windows ใช้ `.venv-voice\Scripts\python.exe` ตั้ง `VOICE_PYTHON` เป็น absolute path ได้ น้ำหนัก ASR ประมาณ 0.5 GB บนดิสก์ การติดตั้ง/ดาวน์โหลดใช้อินเทอร์เน็ต หลังติดตั้ง runtime ไม่ใช้บริการ AI API แต่หน้าเว็บเดิมยังมี Tailwind/Chart/MQTT ผ่าน CDN และ MQTT broker ตาม settings จึงไม่ได้หมายถึงทั้งเว็บตัดอินเทอร์เน็ตได้ทั้งหมด

ไฟล์ `models/whisper-th-small/manifest.json` บันทึกแหล่งและ SHA-256 สำหรับตรวจการติดตั้ง ไฟล์น้ำหนักไม่รวม Git ให้ติดตั้งแยกด้วยสคริปต์ข้างต้น

## การพูด

- กดไมค์แล้วรอเสียงติ๊งเพื่อพูดคำสั่งตรง หรือเปิด “โหมดเรียก Engi” เพื่อรอชื่อก่อนคำสั่ง
- โหมดเรียก: “Engi / เอ็นจี้ / เอนจี้” → รอ “ครับ พูดได้เลยครับ” → เริ่มพูดภายใน 9 วินาที เช่น “เปิดแอร์ให้ผมหน่อย” หรือ “ปิดแอร์” รับคำสั่งได้หนึ่งครั้งแล้วกลับไปรอชื่อใหม่ หมดเวลาจะรอให้เรียกชื่ออีกครั้ง
- “เอ็นจี้เปิดแอร์ให้ผมหน่อย” → ส่งคำสั่งโดยไม่ทักทายคั่น ไม่ต้องเว้นชื่อเป็นอีกประโยค
- “เอ็นจี้ปรับอุณหภูมิ” → ระบบถาม “ต้องการกี่องศาครับ” → พูด “ยี่สิบห้าองศา” โดยไม่ต้องเรียกซ้ำ
- “เอ็นจี้ปรับพัดลมกลาง”, “เอ็นจี้เพิ่มพัดลมหน่อย”, “เอ็นจี้ลดอุณหภูมิ”, “เอ็นจี้โหมดลดความชื้น”
- เมื่อรอชื่อ ประโยค “เปิดแอร์” ที่ไม่มีชื่อจะถูกละไว้โดยไม่สั่งแอร์และไม่ขานตอบ Server ตรวจเงื่อนไขนี้ด้วย และผูกสิทธิ์คำสั่งถัดไปกับเซสชัน/อุปกรณ์เดียว ใช้ซ้ำไม่ได้ ระยะ 9 วินาทีเริ่มหลังเสียงขานรับจบ ถ้าเริ่มพูดทันจะรอให้พูดและถอดเสียงจบตามขีดจำกัด
- พูดหนึ่งประโยคได้สูงสุด 12 วินาที ไม่ใช้ขีดจำกัดเดิม 2 วินาที ถอดเสียงแล้วตรวจ grammar/ค่าตัวเลขก่อนส่ง ไม่ใช้ LLM เดาประโยคอิสระ
- ตรวจ Engi จากข้อความที่ถอดในเครื่อง ไม่ใช่ keyword detector เฉพาะเสียงที่ทำงานระดับระบบปฏิบัติการ การเรียกชื่อยังมีเวลาถอดเสียง และฟังได้เมื่อหน้าเว็บทำงานอยู่
- โหมดต่อเนื่องเก็บประโยคถัดไปได้หนึ่งประโยคขณะ ASR ทำงาน; รอให้ผู้ใช้พูดจบก่อนเล่นเสียงตอบ ไม่ตัดคำกลางประโยค หากมีคำสั่งรออยู่เต็มจะบอกให้รอ
- ระหว่างพูดตอบพักไมค์ ป้องกันเสียงตัวเอง และเว้นหางเสียง 140 ms ก่อนกลับมาฟัง ยังไม่รองรับพูดแทรกเสียงตอบ
- มีการเก็บเสียงข้างต้น/ท้ายราว 320/512 ms และต่อ worklet เข้าทางออกเงียบเพื่อให้ Chrome ประมวลผลกราฟเสียงจริง
- ถ้าสถานะอุปกรณ์เปลี่ยนด้วยคำสั่งอื่นหรือเสียงรอเกิน 20 วินาที จะทิ้งคำสั่งค้างพร้อมแจ้ง ไม่สั่งจากสถานะเก่า
- เมื่อถอดไม่ชัด จะโชว์ข้อความที่ได้ยิน/ขอพูดใหม่ ไม่ลดเกณฑ์ CNN เพื่อบังคับให้ทุกเสียงเป็นคำสั่ง

## อุปกรณ์และขอบเขต

MQTT เดิมยังเป็น JSON `{POWER,TEMP,MODE,FAN}` รองรับ 21–27°C, MODE COOL/DRY/FAN, FAN AUTO/LOW/MED/HIGH สวิง/โหมดนอนและอุณหภูมินอกช่วงจะบอกว่าไม่รองรับ ไม่มีการแอบแปลงเป็นโหมดอื่น

เพิ่ม/ลดอุณหภูมิครั้งละ 1°C ต้องมีสถานะอุปกรณ์ตั้งต้น การสั่งตัวเลขเปิดแอร์ด้วย เทอร์โบแมป COOL 21°C HIGH / Eco แมป COOL 25°C AUTO คงขอบเขต firmware เดิม

เสียงตอบทวนเฉพาะคำสั่งที่ส่ง ไม่อ้างว่า IR ไปถึงแอร์จริง คำปฏิเสธและคำสั่งขัดกันถูกปฏิเสธใน grammar แต่ ASR อาจถอดคำปฏิเสธผิดได้ จึงไม่รับรองว่าป้องกันคำสั่งผิดได้ทุกกรณี

## โมเดลผู้ใช้เดิม

`models/ac_voice_model_int8.tflite` และ metadata เดิมยังเก็บไว้ คู่กับ `offline-voice/worker.py` สำหรับตรวจเทียบและพัฒนาต่อ ไม่มีการใช้ CNN นั้นตัดสินคำสั่งหลักหรือ fallback แบบเงียบ ๆ การแมป metadata ยังใช้เป็น allowlist ของคำสั่งอุปกรณ์ การทดสอบ legacy TFLite/MFCC ต้องใช้ TensorFlow/Librosa ใน requirements ด้วย

## ตรวจสอบ

```sh
npm test
.venv-voice/bin/python offline-voice/test_asr.py
.venv-voice/bin/python offline-voice/test_features.py
```

`test_asr.py` ปิด socket networking ก่อนโหลดโมเดลและทดสอบประโยคผู้ใช้ด้วยไฟล์เสียง Kanya สังเคราะห์ รวมประโยคยาวกว่า 2 วินาที เป็น regression test ของซอฟต์แวร์ ไม่ใช่การประเมินสำเนียงผู้ใช้จริง

ตรวจ Chrome โดยส่งเสียงสังเคราะห์ผ่าน MediaStream 48 kHz → Silero → WAV → ตัวถอดเสียงในเครื่อง → grammar → คำสั่งจำลอง ไม่เรียก callback ข้ามขั้น และปิด MQTT เพื่อไม่สั่งแอร์จริง ส่วนไมค์มนุษย์จริง/เสียงสะท้อนในห้องจริง/ESP32 IR จริง ยังต้องทดสอบหน้างาน

เสียงผู้ใช้ไม่ถูกบันทึกอัตโนมัติหรือส่งไปฝึก หากต้องการ fine-tune สำเนียงผู้ใช้ ต้องเก็บไฟล์เสียงจริงพร้อมป้ายกำกับ และกันผู้พูด/รอบบันทึกไว้ทดสอบ ห้ามใช้คะแนนชุดฝึกอ้างเป็นความแม่นยำหน้างาน
